# 판단 연습 출제 기준

## 목표
개념 이름이나 정답 문장을 암기시키기보다, 어떤 단서를 보고 판단하는지 익히게 한다. 첫 단계는 인원수, 엄폐, 거리, 위험한 스킬, 구도, 역할, 궁극기다. 가이드 본문이 설명의 기준이며, 모든 상황에 적용되는 공식으로 과장하지 않는다.

## 좋은 문제의 조건
- 한 문제에서 핵심 판단 하나를 묻는다.
- 플레이어 시점과 선택 가능한 행동을 명확히 한다. 필요하면 내 영웅·위치·사거리·체력·지원 연결·스킬·시간·목표 상태를 적는다.
- 정답이 달라질 결정적 조건은 본문이나 facts에 공개한다. 해설에서 처음 등장시키지 않는다.
- 제시된 조건에서 가장 알맞은 답 하나를 정한다. 여러 답이 타당하면 조건을 보완한다.
- 오답은 실제 초보자가 할 법한 판단으로 만든다. 터무니없는 선택지, 정답만 유난히 길거나 친절한 형태는 피한다.
- 정답 위치를 다양하게 배치한다. 기존 문제는 형식 참고용이며 출제 품질의 완벽한 표준은 아니다.
- 해설은 '단서 → 판단 → 이유'로 쓴다. 오답은 왜 이 조건에서 부적절한지 설명한다.
- 같은 개념은 조건 하나를 바꾼 문제 쌍으로 확장한다. 단순 문장 바꾸기나 영웅 이름 바꾸기는 별개 학습으로 세지 않는다.

## 꼭 지킬 코칭 기준
- 인원수는 단순 생존자 수보다 지금 공격·지원에 참여하는 인원이다. 다섯 명이 모인다는 것은 한곳에 뭉치라는 뜻이 아니다.
- 리그룹은 기본이지만 지금 목표에 닿지 않으면 경기 종료 같은 조건은 다르게 판단한다. 이미 진 싸움에서는 안전하게 살아서 빠지는 것이 우선이며, 탈출 불가능한 경우 늦게 죽는 것을 피한다. 무조건 죽으라고 하지 않는다.
- 엄폐를 이용해 피해를 줄이고 지원을 연결한다. 힐이 있다고 열린 곳에서 모든 피해를 받아도 되는 것은 아니다.
- CC와 치명적인 공격을 의식한다. 상대가 다른 곳에 써서 스킬이 빠졌어도 기회가 될 수 있다. 스킬이 없다는 사실만으로 무한 추격을 정당화하지 않는다.
- 기본 본대는 탱커·메인딜·섭힐, 사이드는 섭딜·메인힐이다. 상황과 포맷에 따라 달라지므로 고정 위치 규칙으로 만들지 않는다.
- 메인딜이 항상 2층을 써야 하는 것은 아니다. 우리 팀이 쓰지 않아도 상대에게 유리한 자리를 편하게 내주지 않는 것이 중요하다.
- 조합 비교는 상대적이다. 거리·탱커 상성만으로 승패를 단정하지 않는다. 딜·힐·지형·지원도 영향을 준다.
- 방역과 침투의 투자에는 비용이 있다. 다이브는 공격 타이밍을 맞추되, 모두가 동시에 빠져야 한다는 규칙을 만들지 않는다.
- 궁극기의 두 원칙과 예외는 원문을 함께 읽는다. 공격 궁을 빠르게 돌리는 것과 수비궁을 필요한 순간을 위해 보유하는 것을 구분한다.
- 필요한 맞궁은 상대 궁에 즉각 대응해 아군의 생존기와 자리를 지킨다. 모든 상대 궁에 무조건 궁을 누르라는 뜻은 아니다.
- 인원 열세에서 공격 궁을 쓰려면 궁 효과 중 실제 처치로 인원수를 맞출 확실한 킬각이 필요하다. '4대5면 절대 궁 금지'로 바꾸지 않는다.
- 궁을 사용하는 아군의 생존을 우선 케어한다. 승리 가능성이 남은 궁 투자 싸움과 이미 끝난 싸움의 추가 낭비를 구분한다.

## 데이터 형식
questions.json은 문제 객체의 배열이다. 기존 필드를 유지한다.

| 필드 | 뜻 |
| --- | --- |
| id | 고유 식별자. 기존 id 변경 금지 |
| cat | 인원수 / 엄폐 / 스킬 / 궁극기 / 구도 중 하나 |
| chapter | 가이드 장 번호, 정수 0~6 |
| difficulty | 기본 / 응용. 생략하면 기본으로 표시 |
| title | 짧은 문제 제목 |
| scene | count / cover / skill / ult 중 하나 |
| context | 판단에 필요한 조건과 상황 |
| facts | 화면에서 강조할 핵심 조건 문자열 배열 |
| options | 선택지 문자열 정확히 3개 |
| answer | 정답 인덱스. 첫 번째 0, 두 번째 1, 세 번째 2 |
| cue | 기억할 판단 기준 한 문장 |
| why | 정답의 단서와 이유 |
| wrong | 오답을 골랐을 때 보여줄 공통 보충 설명 |

현재 분류는 인원수·엄폐·스킬·궁극기·구도다. 거리 문제는 cat=구도, chapter=2로 쓸 수 있고 역할 문제는 cat=구도, chapter=5로 작성할 수 있다. 새 분류·scene은 화면 코드 수정 전 임의로 추가하지 않는다. 목록 표지는 주제별 선 그림 5종을 공유한다. 이는 주제를 나타내는 장식이며 실제 상황의 배치를 뜻하지 않는다. 풀이 화면의 32개 문제는 모두 현재 배치 개념도와 상황 설명, facts를 표시한다. scene 값만으로 실제 거리·인원·엄폐를 그리지 않는다. 상세 배치가 필요한 문제에는 지원되는 diagram 데이터를 별도로 제공한다.

## 검토용 초안
JSON과 별도로 PR 설명 또는 초안 문서에 아래를 적는다. 사이트 데이터에 임의 필드를 넣지 않는다.
- 관련 원문: 장·소제목·직접 인용한 짧은 근거
- 학습 목표와 핵심 단서
- 1·2·3번 선택지가 각각 맞거나 틀린 이유
- 조건 하나가 바뀌면 정답이 바뀌는 예
- 패치 검증이 필요한 사실과 확인 상태
- 사람 검토 상태: 미검토 / 수정 필요 / 승인

## 사람 검토 체크리스트
- 상황에 없는 사실을 해설에서 가정하지 않았는가?
- 다른 선택지가 더 나을 합리적인 상황이 현재 조건에 남아 있는가?
- 가이드의 기본 원칙과 예외를 함께 지켰는가?
- 초보자가 쓰지 않는 말은 설명했는가?
- 기존 문제와 핵심 판단이 중복되지 않는가?
- 형식 검사와 코치 검토를 모두 거쳤는가?



## 선택 사항: 인원수 배치도
기존 인원수 문제 3개는 `participation`, 나머지 29개는 `situation` 배치도를 사용한다. 다른 필드는 그대로 유지한다.

```json
"diagram": {
  "type": "participation",
  "allies": {"main": 4, "side": 0, "joining": 1},
  "enemies": 5
}
```

main은 정면에서 준비된 아군, side는 다른 위치에서 같은 싸움에 공격할 준비가 된 아군, joining은 아직 공격·지원할 수 없는 아군이다. 각 값은 0~5의 정수이고 아군 합은 1~5, 상대 인원은 1~5다. enemies는 현재 교전 준비가 된 상대 인원이다. 적의 합류·고립 등 추가 상태는 아직 지원하지 않는다. 이 형식으로 정확히 표현할 수 없는 문제에는 배치도를 붙이지 않는다.

문제에 적힌 조건만 도식화한다. 영웅·엄폐·지원선·실제 맵 경로를 임의로 추가하지 않는다. 위치는 개념 배치이며 정확한 거리나 사선을 보장하지 않는다. 참여 인원 해석은 정답 확인 뒤 표시하고, 다시 풀기에서는 숨긴다. scene은 목록 카드의 주제 표지용으로 유지한다. 배치도 없는 풀이 화면에 표지나 중복 단서 카드를 삽입하지 않는다.

## 난이도와 정답 위치
현재 기본 22개와 응용 10개다. 기본은 한 가지 기준, 응용은 여러 조건의 우선순위를 비교한다. 정답 위치는 개별 문제에서 길이나 문체로 드러나지 않도록 하고 전체 분포는 검사 스크립트의 경고를 확인한다. 경고는 정답의 타당성을 대신하지 않는다.

## 가이드 소단원
5장 구분은 app.js의 chapterFiveParts와 제목 기반 sliceGuideSection으로 찾는다. 경계 제목은 유일해야 하며 변경 시 연결 설정과 화면 검사도 함께 수정한다. 본문·그림을 추가해도 숫자 인덱스를 수정할 필요는 없다.


## 상황 배치도 (`situation`)
공통 현재 배치 프레임과 아군·상대 원형 표식을 사용한다. `rows`는 1~5개이며 각 행은 `team`(ally/enemy/mixed/terrain), `label`(상황 설명), `units`(최대 5개의 표식 문자열)를 갖는다. terrain은 지형·조건 구분선이다. mixed 행의 `적` 표식은 상대 색으로 표시된다. 전체 인원이 명시되지 않은 경우 등장 대상만 그리며, 범례에 이를 안내한다. 정답 행동을 그림에 미리 표시하지 않는다.

판단 연습에서는 황족 등 자체 비유를 사용하지 않는다. 탱커·메인딜러·서브딜러·메인힐러·서브힐러, 리스폰, 리그룹은 사용할 수 있다. 사망 후 재등장은 리스폰, 교전 시작 움직임은 진입으로 표현한다.


## 배치도 인원 표시
인원수 자체가 핵심이 아닌 상황은 두 영웅의 1대1 비교 또는 양 팀 5명의 전체 표식으로 표시한다. 전체 팀 표시에는 `roster: "full"`을 지정한다. mixed 행에서 `적`으로 시작하는 표식은 상대다. 사망·리스폰 표식은 회색 점선으로 표시해 참여 인원과 구분한다. 나머지 인원의 구체적인 위치는 가정하지 않고 별도 행에 표시한다.
